Rule for new UI work:
- Before building a custom interactive UI element, check this file and apps/web/src/components/ui.
- If shadcn already provides the pattern, install/use the shadcn component first.
- Keep custom logic only for project-specific behavior, data transforms, or domain workflows.

Frontend audit notes:
- Prefer Alert for API/user-facing errors instead of standalone styled paragraphs.
- Prefer Empty for empty states instead of repeated dashed sections.
- Prefer Context Menu for right-click actions instead of manual x/y menu positioning.
- Keep native hidden file inputs when they are only an implementation detail behind a shadcn Button.
- Use AlertDialog for all destructive confirmations (delete, remove). AlertDialogAction/Cancel wrap Button internally — no asChild needed.
- Use Field/FieldLabel inside all form groups. Use FieldError for per-field validation (accepts errors array). Keep Label for non-field-group uses (checkboxes, permission group headers).
- Use Tooltip wrapping icon-only buttons. TooltipProvider with delayDuration=0 is in providers.tsx.
- Use Item/ItemGroup for list rows with media + content + actions layout. Use ItemGroup for vertical lists, keep grid layout for 2-column card grids.
- Use toast.success("...") from sonner in all mutation onSuccess callbacks.
- Consider Input Group for money (€) and rate (€/h) input fields with suffix/prefix labels.
